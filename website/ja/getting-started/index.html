運用モデル

エージェントがデザイン。
IconFlow がプルーフを担う。

エージェントは製品を調査し、異なるコンセプトを探り、セマンティック SVG を作成します。IconFlow はプレイブック、決定論的レンダラー、品質ゲート、ターゲット変換、学習ループを提供します。プロンプトから画像を生成するツールではありません。

進め方を選ぶ

二つの入口。
品質ゲートは一つ。

製品の考え方や SVG 制作の支援が必要なら、エージェント経由を選びます。デザイン判断を自分で担うなら、CLI 経由を選びます。どちらも同じレビュー契約に到達します。

推奨エージェント支援

絵ではなく、製品の役割を伝える。

オープン形式の IconFlow スキルをインストールします。対応するエージェントなら、アプリアイコン、favicon、ロゴマーク、トレイアイコンを頼むとワークフローを検出できます。

Windows · PowerShell

git clone https://github.com/snowyukitty/ai-iconflow.git
cd ai-iconflow
python -m venv .venv
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
.\.venv\Scripts\python.exe -m iconflow doctor
.\.venv\Scripts\python.exe -m iconflow ship `
  --config brand\iconflow.toml `
  --review brand\master-review.json `

完全なループ

すべてのコマンドに
役割がある。

これらは利用側のプロジェクトから実行します。IconFlow の仮想環境にある Python を絶対パスで使い、設定と最終ソースを対象の製品と同じ場所に保ちます。

  1. 01
    ブリーフ

    製品契約を書く。

    描く前に意図を記録します。設定では、ターゲット、色、パス、トレイの動作も固定します。

    python -m iconflow init --out iconflow.toml \
  --name "My App" --essence proof \
  --targets web,tauri,electron,tray
  2. 02
    探索

    異なるビジュアル案を必ず出す。

    異なる視点から少なくとも 4 つのコンセプトを作成します。技法プリセットは足場であり、完成したアイデンティティではありません。

    python -m iconflow styles
python -m iconflow new flat-geometric \
  --out work/my-app/a.svg
  3. 03
    比較

    磨き込む前に形を選ぶ。

    最終候補を 2 つか 3 つまとめてレンダリングします。シートを 128px、16px、シルエットで確認します。

    python -m iconflow compare \
  work/my-app/a.svg work/my-app/b.svg \
  work/my-app/c.svg --out work/my-app/bake.png
  4. 04
    検査

    実際のターゲット変換をレビューする。

    すべての警告を解消します。次に、ネイティブピクセル、アルファ、アダプティブクロップ、デスクトップの角、トレイでの表示を確認します。

    python -m iconflow check master.svg
python -m iconflow review --config iconflow.toml \
  --out work/my-app/review.png \
  --html work/my-app/review.html
  5. 05
    リリース

    承認はフェイルクローズにする。

    すべての評価軸が 4/5 に達してから、Review Lab の receipt をエクスポートします。ソースまたはターゲットを変更すると、その receipt は無効になります。

    python -m iconflow ship \
  --config iconflow.toml \
  --review master-review.json
  6. 06
    学ぶ

    学びをシステムに戻す。

    最初に何が失敗し、何を変えたか、再利用できるルールを一つ記録します。記録されないアイコンからは何も学べません。

    python -m iconflow case new ...
python -m iconflow case lint
python -m iconflow case stats

出力ファミリーの仕様

リリースする
サーフェスだけを指定。

ターゲットは明示的です。IconFlow は「全プラットフォーム対応」をうたいません。また、全面を使うアプリカードが暗黙に実用的なメニューバー用シルエットへ変わることもありません。

WEB / PWA

ブラウザ向けサーフェス

favicon の SVG と ICO、Apple touch icon、192px と 512px の PWA アセット、さらに maskable icon と manifest スニペット。

--targets web,pwa
TAURI

デスクトップバンドル

PNG の各サイズ、ICO、ICNS、および Tauri v2 デスクトップアプリ向けの標準的な src-tauri/icons レイアウト。

--targets tauri
ELECTRON

パッケージャー入力

Electron と electron-builder のパッケージングワークフロー向け、クロスプラットフォームの PNG、ICO、ICNS アセット。

--targets electron
TRAY

メニューバー用マーク

カラートレイ PNG、macOS テンプレートアセット、TypeScript ヘルパー。マーク専用の tray.svg を強く推奨します。

--targets tray

既知の制約

ローカルだからといって
魔法ではない。

  • 現時点ではソースからインストール。IconFlow はまだ PyPI で公開されていません。公式リリースが出るまで pip install ai-iconflow は使わないでください。
  • 初回のみダウンロード。セットアップ時は、依存パッケージと Playwright Chromium の取得にネットワーク接続が必要です。その後のレンダリングとビルドはローカルで行われます。
  • デスクトップの範囲。現在の Tauri 出力が対象とするのはデスクトップアセットです。Android や iOS の起動画面とアイコンセットは含みません。
  • ツールチェーンに依存するプルーフ。再現性には、同じ正規化済み SVG、設定、IconFlow、Chromium、Pillow のバージョンを使うことが前提です。
