# Discoverability

How IconFlow gets found — by a search engine, by an answer engine, and by a
developer scrolling GitHub. Written 2026-08-24 after the 0.5.0 launch; updated
2026-08-27 when the first problem-specific reference vertical shipped.

## The diagnosis

The site was well built and ranked for nothing.

Twenty-four URLs were in the sitemap and every one of them was a *brand* page:
the homepage, getting started, the methodology essay, the archive, the gallery
collections, in five languages. Each is excellent at converting someone who
already knows what IconFlow is. None of them is what anyone types into a search
box.

The queries that carry this category's traffic are specific and boring:

- *how many favicon sizes do I need*
- *favicon.ico sizes*
- *maskable icon safe zone*
- *tauri icon sizes*
- *electron icon size windows mac linux*
- *macOS menu bar icon black square*
- *app icon looks bad at 16px*

Those searches land on `realfavicongenerator.net`, `favicon.io` and
`icon.kitchen`. IconFlow was not competing for them, because it had no page
that answered them. A homepage that says *One master. Every surface.* is a
brilliant thing to read and a hopeless thing to rank: it contains none of the
words a person in trouble is typing.

The second problem was structural. The homepage published `WebSite` and
`SoftwareSourceCode` structured data and nothing else — no statement of what
kind of application this is, which platforms it runs on, or that it is free.
Three of the four collection pages published no structured data at all.

## What shipped

### 1. A reference page that cannot lie

[`/reference/icon-sizes/`](https://ai-iconflow.com/reference/icon-sizes/) is the
demand-capture page: every icon file each supported target needs, with exact
filenames and frame sizes, the paste-ready `<head>` block, the generated
manifest, the maskable safe-zone rule, and nine FAQ answers.

It is generated by `scripts/build_reference.py`, which reads
`iconflow.build.preview_assets`, `ICO_FRAME_ORDER`, `ICNS_FRAME_SIZES`,
`TAURI_PNG_SPECS` and `assemble.maskable_asset` — the same code paths a real
`ship` runs. A build change that has not been re-rendered fails
`tests/test_website.py`, and a new output file with no description fails the
generator outright.

This matters beyond tidiness. Every competing size table on the web is a human
transcription that drifts the moment a platform changes, and readers have no
way to tell a current one from a stale one. IconFlow's cannot drift without
breaking CI, and the page says so. That is a durable reason to link to it,
which is the only ranking signal that actually compounds.

The page also does the job the homepage cannot: it meets a reader mid-problem
("what size is a tray template?"), answers it completely, and only then
explains that the answer came from a tool that would have produced the file.

**What the edge does to it.** Three filenames on the page —
`icons/128x128@2x.png`, `tray/tray@16.png`, `tray/trayTemplate@2x.png` — read
as email addresses to a CDN. Cloudflare's Email Address Obfuscation, on by
default, replaced all three at the edge with `[email protected]` links. The
repository was right and the served page was wrong, on the one page whose
entire premise is that it cannot drift. The generator now emits `&#64;`, which
parses to the same character for a reader, a copy-paste and a crawler while
matching no email pattern, and refuses to write a page carrying a literal `@`
outside the JSON-LD block. Nothing in the repository could have caught this:
the rewrite happens after the bytes leave it. `scripts/state.py` found it by
comparing the deployed page against the checkout.

### 2. Structured data that describes the software

- Homepage: `SoftwareApplication` — category, subcategory, operating systems,
  version, requirements, install URL, feature list, and `isAccessibleForFree`.
  Deliberately **no** `offers` and **no** `aggregateRating`: nobody has rated
  or sold this, and rich-result markup for a rating that does not exist is the
  one kind of claim the rest of the site refuses to make. The website tests
  enforce both absences.
- Reference page: `TechArticle` + `FAQPage` + `BreadcrumbList`.
- All four collection pages: `CollectionPage` + `ItemList` + `BreadcrumbList`,
  where before there was nothing.
- Every indexed page is now tested for a distinct, non-thin title and
  description. Duplicate titles are the cheapest ranking loss there is.

### 3. An internal link graph

The reference route is linked from the homepage's closing call to action and
from the footer of every page, including the four translated language trees,
where the label is translated but the URL stays canonical. It is in the
sitemap, has its own cache header, and is exempted from the training-crawler
block (see below).

### 4. GitHub

- The README opens with `docs/assets/demo.gif`: a real captured run in which
  `ship` builds 23 files, one control point moves in the master SVG, and the
  same command refuses. Ten seconds, no prose, and it demonstrates the one
  thing no competitor does. The transcript it is drawn from is checked in, and
  `scripts/render_readme_demo.py` regenerates it through the same pinned
  Chromium every other rendered asset uses.
- Topics went from 12 to GitHub's maximum of 20, adding `icon-generator`,
  `icons`, `svg-to-png`, `maskable-icons`, `macos`, `developer-tools`,
  `progressive-web-app` and `claude-code`. Topic pages are browsed inside
  GitHub and indexed outside it.
- The animation and its transcript are excluded from the wheel. Half a
  megabyte of GIF has no business in a package that never displays it.

### 5. The black-square failure, reproduced rather than described

[`/reference/tray-icons/`](https://ai-iconflow.com/reference/tray-icons/) now
owns the distinct search intent *macOS menu bar icon black square*. It shows
three outcomes at real 32px source resolution: an opaque app card converted by
`alpha`, the same card recovered by `auto`, and the preferred dedicated
`tray.svg` converted by `auto`.

The five evidence PNGs are generated by `scripts/build_tray_reference.py` from
IconFlow's checked-in app and tray outputs through
`iconflow.assemble.to_template`. The generator verifies that its preferred
result is byte-identical to the tray template IconFlow actually ships. The
HTML, every PNG, the exact tray file table, the sitemap entry, cache contract,
answer-engine link and inbound links are covered by website tests and the
project self-audit. A change to the conversion cannot leave a confident old
illustration online.

Apple's `NSImage.isTemplate` and `MenuBarExtra` documentation and Electron's
`Tray` and `nativeImage` documentation are linked as primary sources. The page
keeps the product boundary explicit: IconFlow's tray feature-loss report is an
early diagnostic; the source-bound review receipt remains the final ship gate.

Its route-specific 1200×630 social card is rendered by the existing
network-isolated marketing renderer from those exact evidence PNGs and added to
the SHA-256 manifest. It is a useful summary image, not a substitute for the
page or the native-pixel evidence.

### 6. The first proof now starts from the release

A fresh isolated install on 2026-08-27 proved that the public 0.5.0 wheel can
complete the full `demo --setup` path and write its 23 source-bound outputs.
The adoption copy had nevertheless drifted in two opposite directions: the
website sent visitors to a source checkout, while the live PyPI description
still warned that the package was not published.

README, homepage, and Getting Started now lead with the same two-command path:
install the wheel, then run `iconflow demo --setup --out iconflow-demo`.
`scripts/build_adoption.py` makes copy drift fail offline, and the project
self-audit separately reports stale live PyPI description text. The checkout
is fixed now; PyPI will stay honestly red until a future justified release
replaces the already-published metadata. No version was created for SEO copy.

## Answer engines

By 2026 a large share of "which favicon sizes" questions are answered by a
model, not a result page, and the citation goes to whatever the model can
read and trust. IconFlow is unusually well placed for this and was giving some
of it away.

`llms.txt` was already in place. What changed is `robots.txt`. The named
training-crawler block that protects the licensed corpus — the CC BY-SA
methodology and the CC BY-NC-ND artwork — now carries an explicit
`Allow: /reference/`.

That is a deliberate line, not a loosening. The archive, gallery and
methodology took the longest to earn and are licensed restrictively; they stay
out of bulk collection. The reference tables are generated from Apache-2.0 code
and state facts about *other people's* platforms. They exist to be quoted, and
a citation to `ai-iconflow.com` from inside an answer is worth more than a
ranking.

**Open question for the owner.** `/how-icons-are-made/` is the single most
citable page on the site and is currently blocked to `GPTBot`, `ClaudeBot`,
`PerplexityBot` and the rest. That is a defensible choice — it is the
methodology, it is CC BY-SA, and share-alike is unenforceable against a model.
But it is the main remaining lever between *protect the corpus* and *be the
source models cite*, and it should be a decision rather than an inheritance.

## The queue

Ranked by expected traffic per hour of work. Each would be a generated,
source-bound page under `/reference/`, following the same contract.

| Page | Captures | Source of truth |
|---|---|---|
| `/reference/16px/` | *icon unreadable at 16px*, *icon too detailed* | the review renders, plus real before/after pairs from the archive |
| `/reference/favicon-head/` | *favicon html code*, *favicon meta tags* | `htmlhead.head_snippet` and `manifest` |
| `/reference/tauri-icons/` | *tauri icon sizes* | `TAURI_PNG_SPECS`, `ICO_FRAME_ORDER` |
| `/reference/electron-icons/` | *electron icon sizes* | `electron_frames`, `DESKTOP_FRAME_SIZES` |

Split only where the intent genuinely differs; the current icon-size page with
deep anchors is better than five thin ones. `/reference/tray-icons/` earned the
first split because the black-square failure is a distinct problem with
distinct search language and a source-bound visual reproduction. The next
candidate is `/reference/16px/`, but only real impression data or repeated user
questions should promote it from the queue.

Not on the queue, on purpose: comparison pages against named competitors, and
any page whose content is not generated from something that can go stale
loudly.

## Only the owner can do these

1. **Upload the repository social preview.** `usesCustomOpenGraphImage` is
   still `false`, so every link to the repo — in a chat, an issue, a tweet —
   renders GitHub's generic grey card instead of the brand image.
   `docs/assets/social-preview.png` is already the right 1280×640. It cannot be
   set through the API: *Settings → General → Social preview → Upload*.
2. **Decide on Discussions.** `gh repo edit snowyukitty/ai-iconflow
   --enable-discussions`. Discussion threads are indexed, and a public place to
   ask "what size does X need" feeds the queue above with real language. It
   also creates a moderation surface; `CODE_OF_CONDUCT.md` is in place.
3. **Google Search Console and Bing Webmaster Tools.** Verify
   `ai-iconflow.com`, submit `sitemap.xml`, and watch which of the reference
   page's anchors earn impressions. Without this the queue above is guesswork.
4. **Turn off Cloudflare's automatic Web Analytics injection**, or decide to
   keep it. Found by `scripts/state.py` on 2026-08-25: the edge injects
   `static.cloudflareinsights.com/beacon.min.js` into every HTML page, and this
   site's `Content-Security-Policy` is `script-src 'self'`, so every visitor's
   browser blocks it and logs a violation. The analytics therefore collect
   nothing while the console is never clean — the worst of both. Either disable
   automatic injection in the dashboard, or add the host to the CSP and accept
   a third-party script on a site whose pitch is that nothing leaves your
   machine. The first is the choice that matches the product.
5. **Settle the `/how-icons-are-made/` question** above.

## How to know it worked

Judge the reference page on **impressions**, not sessions, for the first eight
weeks — a new page takes that long to be trusted for competitive terms, and
impressions move first. The signals worth watching, in order:

1. impressions on non-brand queries (anything not containing "iconflow");
2. which anchor sections earn them — that is the queue, told by real demand;
3. citations in answer engines, checked by hand, since none of them report;
4. GitHub stars per unique visitor, which is what the README animation moves;
5. sessions and installs, which lag all of the above.

Brand queries are not a measure of any of this. They were always going to find
the site.
