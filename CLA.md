it is written to be read rather than clicked past.

grant, not an assignment. You can reuse your own contribution anywhere else, in
any way, forever, with no permission from anyone.

What it gives the project is the right to keep the code distributable — and, if
IconFlow's licensing ever has to change, the ability to make that change without
tracking down every past contributor for individual permission. A project that
cannot relicense is a project frozen by its first outside pull request.

## 5. How to sign

Include this line in your pull request description, filling in your name and the
date:

```
I have read CLA.md and I agree to it.  Signed: <your full name>, <YYYY-MM-DD>
```

For a contribution made on behalf of a company, add the company's name and
confirm you are authorised to bind it.

Also sign off each commit with `git commit -s`, which certifies the
[Developer Certificate of Origin](https://developercertificate.org/). The DCO
and this agreement do different jobs and the project uses both: the DCO records
the origin of each commit, and this agreement records the license you granted.

## 6. Why a CLA and not only a DCO

Most projects use a DCO alone, and it is the lighter-weight choice. IconFlow
asks for both because of one specific scenario the maintainer wants to keep
answerable: the engine is Apache-2.0 today, which permits anyone to modify it
and ship the result in a closed product. If that ever becomes a real problem
rather than a theoretical one, the response is to change the license — and that
response is only available to a project that holds the rights to do it.

This is stated openly rather than left implied. If it is a reason not to
contribute, that is a fair conclusion to reach, and the project would rather you
reach it having read the actual terms.
